Área de conteúdo variável

Onde cada wizard-* renderiza. Aqui é placeholder; nos cenários (Etapa 2) cada um vira form, lista, calendário, comparativo. A largura escolhida afeta os 8 conteúdos futuros.

✓ escolhida
ALargura completa
Conteúdo ocupa toda a largura disponível (max 100%). Bom para conteúdos densos (calendário coletas, lista carriers, comparativo pool).
··· conteúdo full-width ···
(calendário · tabela densa · multi-coluna)
flexível para conteúdos densos; passos textuais (welcome, pool-bh) ficam "perdidos" em tela larga
BLargura limitada centralizada
Max-width ~720px, centralizado. Estilo wizard guiado clássico. Foco e leitura confortável.
··· conteúdo centralizado ···
(form · texto · escolha)
conforto de leitura; calendário ou tabela grande não cabe — precisaria scroll horizontal
CCards sequenciais empilhados
Cada subtarefa do passo num card vertical. Bom para passos com múltiplas decisões (carriers: credencial + tabela).

Resumo: 5 regiões × 3 variações = 15 mini-sketches para validar.
Pontos críticos detectados: (1) R1 e R3 são complementares — escolha de R1=B (8 steps) torna R3 redundante; R1=A com R3=A dá visão dupla. (2) R4 (largura) afeta os 8 conteúdos futuros — A (full) é melhor para coletas/carriers; B (limitada) é melhor para welcome/pool-bh. (3) Auto-save é universal em todas variações de R5. (4) Fase 5b (tabela contrato fallback) é desvio para `importar-contrato-preview`; o shell precisa suportar "passo opcional" como variante de R2/R5.
