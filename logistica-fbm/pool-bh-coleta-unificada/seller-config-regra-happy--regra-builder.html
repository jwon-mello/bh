Resumo: 5 regiões × 3 variações = 15 mini-sketches para validar.
Pontos críticos detectados: (1) R3 e R4 devem ter mesmo padrão — coerência visual entre "se" e "então"; misturar A com C cria fricção. (2) "Simular" é guard-rail — antes de salvar, seller pode testar contra pedidos passados (cenário "conflito-detectado" mostra resultado). (3) Auto-sugestão de nome aparece em R2 nas 3 variações — sugestão baseada em categoria + condição preenchida. (4) Categoria afeta R3/R4 — Roteamento mostra campos canal/país/peso → origem/carrier; Embalagem mostra peso/país → caixa.
Combinação validada ✓: 1A · 2A · 3B · 4A · 5C
Observação: R3=B (chips clicáveis para condição) + R4=A (dropdowns inline para ação) usam padrões diferentes intencionalmente — chips para o lado mais aberto (condição com múltiplos campos), dropdowns para o lado mais determinístico (ação com poucas opções). Validar em protótipo se a quebra de simetria é confortável.
